问题

马来西亚的日常金融计算分布在不同的网站、文件和技术规则中。

人们在比较住房贷款、估算税收或计划 EPF 储蓄时需要快速得到答案，然后才需要专业建议。许多现有工具杂乱无章，假设不透明，或者要求提供个人详细信息。

解决方案

我为七个常见决策设计了一个一致的、无需注册的工具箱。

每页一个任务

每个计算器仅显示该决策所需的输入，然后是可读的细目分类。

局部优先计算

输入和结果保留在浏览器中。不存在帐户、数据库或分析依赖性。

马来西亚的具体情况

RM 格式、本地术语、渐进式括号和官方源链接使这些工具更易于理解。

我的职责

我将套件从机会转变为部署的产品。

我定义了计算器范围，设计了界面，实现了计算逻辑和响应式前端，编写了解释性和 SEO 副本，添加了验证注释，并通过 GitHub 和 Vercel 部署了网站。

关键决策

小堆栈是产品决定，而不是工程的缺失。

普通 JavaScript

每个页面加载速度都很快，可以在基本托管上运行，并保持公式可见和可维护。

无后端

计算器不需要传输财务输入，从而降低了隐私和基础设施风险。

渐进式披露

高级字段和详细细分仅在有用时才会出现，从而使首次交互变得平易近人。

发生了什么变化

7

实时工具现在共享一种产品语言和一种隐私优先模型。第二次迭代在信任审查后添加了官方源链接、更新日期、工作示例和更清晰的限制。

我学到了什么

财务用户体验不仅仅是让公式运行。用户需要查看假设、来源、日期和计算细目，然后才能决定对结果的置信度。
