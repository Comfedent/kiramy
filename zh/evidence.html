产品证据

每个项目成熟度不同。这个页面把已上线功能和计划中的验证分开，避免把概念包装成结果。

线上 / 教育型

KiraMY

现在可用七个马来西亚财务计算器、本地浏览器计算、结果拆解、下一步模块、官方来源链接，以及已迁移工具的规则元数据。

尚未证明尚未测量：重复使用、用户信任、商业转化、合作方需求，以及所有边缘场景的规则准确性。

下一步验证继续扩展规则版本和测试用例，并加入隐私友好的计算差异反馈。

线上 / 本地优先

Shiye Notes

现在可用新建、编辑、搜索、置顶、删除笔记；自动保存；损坏数据恢复；JSON 导入导出和备份提醒。

尚未证明尚未测量：长期留存、用户备份行为、跨设备需求，以及用户是否信任浏览器本地存储。

下一步验证测试用户是否理解导入导出，并探索敏感笔记的可选客户端加密。

线上原型

KiraStart MY

现在可用第一年预算引导流程、马来西亚到手收入估算、建议、36 个月里程碑、本地保存、JSON 导入导出和打印摘要。

尚未证明需要用户测试：输入是否准确、建议是否有用、场景是否贴近现实，以及用户是否会采取行动。

下一步验证加入情境对比，并补充法定扣款和 PTPTN 假设的官方规则说明。

概念验证

Bukit Pala

现在可用Landing page、礼盒概念、商业假设、验证计划、单位经济类别、运营检查表和 go/no-go 标准。

尚未证明概念阶段：需求、供应商稳定性、保质期、批发价、包装时间和履约问题尚未验证。

下一步验证先做供应商和买家访谈，再测试无付款兴趣表单，之后才考虑付费小批量试点。

工程证据

这里的工程重点不是复杂框架，而是边界清楚、逻辑可测试、可靠性路径明确。

已有测试

Node built-in test 覆盖 Shiye 笔记状态、LocalStorage 导入导出、KiraStart 计划存储，以及计算器规则示例。

  • 损坏笔记数据恢复
  • JSON 导入格式验证
  • 合并导入不删除原有数据
  • 所得税、房贷、EPF 和车贷计算测试样例
计算逻辑

Income tax 和 home loan 页面已接入共享规则与计算模块。EPF 和 car loan 已有纯计算模块用于测试，其余页面仍是计划迁移。

LocalStorage 恢复

Shiye Notes 与 KiraStart MY 都能处理损坏的本地数据，不会直接崩溃；两个项目也都说明浏览器本地存储边界，并提供 JSON 可携带性。

响应式 QA

关键中英文页面经过移动端浏览器 smoke test，测试流程中没有横向溢出。

可访问性说明

核心页面使用语义化 section、清晰按钮文字、状态文本和键盘友好控件。更完整的屏幕阅读器测试仍属于计划验证。

来源和更新时间

KiraMY 计算器页面展示官方来源、复核日期和规则元数据。已迁移规则包含 ruleVersion、effectiveYear、sourceName、sourceUrl、lastUpdated、assumptions 和 knownLimitations。

当前限制：并非所有计算器页面都已完成 DOM 到模块的迁移。这个限制被明确记录为后续可靠性工作，而不是隐藏起来。

商业证据

商业证据和视觉包装分开呈现。没有数据的地方，不编造。

KiraMY

教育型计算器套件，下一步是反馈闭环、SEO 内容闭环和可选规则更新提醒。用户量、转化和收入尚未测量。

Shiye Notes

本地优先写作工具，已补强数据可携带性。商业需求尚未测量；下一步是验证用户是否愿意用备份机制换取浏览器本地隐私。

KiraStart MY

第一年财务计划引导工具。未来证据应来自情境对比使用、导出计划和用户对建议的反馈。

Bukit Pala

本地礼盒概念的预购验证计划。在定价、收款或备货前，仍需要供应商和买家研究。
